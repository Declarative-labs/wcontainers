# The WebGPU back end's committed plant list for the text cargo-mutants never mutates: the WGSL strings of
# fill.rs on the paths the 24-bit depth work added (the read of stored 24-bit depth, `unorm24` and the two
# conversions it checks against; the float nearest a 24-bit word; the comparison pass; the read and depth
# programs' shift), one plant per operator and constant, and the Rust arguments that feed those programs.
# Every plant keeps the WGSL valid, so it compiles and the device builds it; each must make a test fail.
# Run from the repository's root inside its `nix develop`, with lavapipe named as unit_tests/scenes.rs says
# (VK_ICD_FILENAMES, WEBGPU_API=vulkan) and WCONTAINERS_SPIRV_TOOLS set:
#   python3 -I tools/plants/run-plants.py crates/gpu/implementation/webgpu/plants.txt --workers 3
# Not planted (said, not silent): depth_of_float_bits (a NaN written as depth becomes zero; GI2's, not the
# 24-bit work), the clear, stencil, present, resolve and packing programs, and COVER_WGSL, which every
# program of the back end draws with.
# No plant changes how unorm24 takes the whole part of d (2^24 - 1): for every word under both conversions
# the product rounds to a whole number (unit_tests/unorm24_read.rs runs all 2^24; truncating, rounding and
# taking the ceiling were each planted on 2026-11-27 and gave the same words), so the choice is no operator.
